---
title: 0.54 から 0.55 への移行
description: 本番 Murasaki アプリを更新するための破壊的変更と検証チェックリスト。
---

Murasaki 0.55 では runtime authority、update、packaging、browser data の identity を
強化しました。多くのアプリは構造を変えずに compile できますが、以下は意図的な
fail-closed 変更です。desktop build を公開する前に対応してください。

## 1. renderer の環境変数を変更する

renderer JavaScript に埋め込んでよい値には `MURASAKI_PUBLIC_*` を使います。

```dotenv
MURASAKI_PUBLIC_API_ORIGIN=https://api.example.com
DATABASE_URL=postgresql://localhost/private
```

renderer から見えるのは1つ目だけです。credential には prefix を付けないでください。
既存アプリ固有の public prefix が必要なら `build.envPrefix` へ明示し、空 prefix は公開しないで
ください。

## 2. update manifest に `generatedAt` を追加する

`murasaki release --manifest` が作る新しい manifest には `generatedAt` が含まれます。
これを持たない legacy manifest は既定で拒否されます。期間を区切った移行時だけ、次を設定
できます。

```ts
updater: {
  allowLegacyManifestsWithoutGeneratedAt: true,
}
```

support 対象の全 installed version が新 manifest を読めるようになったら削除してください。
0.55 は認証済み manifest の最高 timestamp / version も永続化し、古い署名済み manifest を
replay / rollback として拒否します。

## 3. executable resource を宣言する

sidecar や helper binary には structured resource を使います。

```ts
bundle: {
  resources: [
    { from: 'bin/helper', to: 'sidecars/helper', executable: true },
  ],
}
```

これにより app / installer を seal する前に helper も署名されます。宣言されていない Mach-O、
PE、ELF、shebang resource は、後から Gatekeeper や Windows policy に拒否される artifact を
生成せず、packaging 時点で停止します。

## 4. 永続化した app origin を利用可能に保つ

0.55 は packaged app の初回起動で loopback port を1つ選び、永続化します。次回以降にその
port が使用中なら、別 origin へ移って localStorage / IndexedDB が空に見える動作をせず起動に
失敗します。無関係な local service がこの port を占有しないようにしてください。collision が
表示されたら競合 process を停止します。origin state の削除は新しい browser-data identity を
作る操作であり、通常の復旧手順ではありません。

## 5. capability 境界を見直す

- native API と Node Main / API route は別々の default-deny surface です。
- native grant は `capabilities`、Node / API grant は `backendCapabilities` に、可能なら window
  単位で宣言します。
- camera、microphone、geolocation の browser API は framework response policy が拒否します。
  対応を追加する場合は app-owned native flow を用意し、同等の境界なしに header を弱めないで
  ください。
- `sign.appSandbox: true` は拒否されます。sandbox-compatible な Node helper model が文書化
  されるまでは macOS Hardened Runtime + notarization を使用してください。

## 6. 実 target で release を検証する

最低限、次を実行します。

```bash
pnpm typecheck
pnpm test
pnpm exec murasaki build
pnpm exec murasaki bundle --target <platform-arch>
pnpm exec murasaki installer --target <platform-arch> --sign
```

macOS では codesign、Gatekeeper、staple 済み notarization ticket を検証します。Windows では
Authenticode を検証し、security control を有効にしたまま installed app を起動します。
Gatekeeper、SmartScreen、Smart App Control の無効化を利用者向け手順に含めないでください。
