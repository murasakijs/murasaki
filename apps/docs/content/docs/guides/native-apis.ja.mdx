Murasaki のネイティブウィンドウ、メニュー、OS 統合は
[`@murasakijs/native`](https://www.npmjs.com/package/@murasakijs/native) —
自社製の Rust バインディング(tao/wry/muda)— によって支えられているため、Rust を書く
ことは一切ありません。このページでは、**あなたの React アプリから**実際に到達可能なも
のを説明します。

## ウィンドウとネイティブメニューバー

windowのshape（サイズ、title、route、表示、permission、macOS vibrancy）は
`murasaki.config.ts` で宣言します。`window` はprimaryの`main`、`windows` はlabel付き
secondaryです。全体像は[ウィンドウと権限](/ja/docs/guides/windows)を参照してください。

macOS では、標準的な App/Edit/Window メニューバー(About、Services、Hide、Quit、
Edit、Window)が自動的に生成され、`config.locales` からローカライズされます — コード
は不要です。

## コンテキストメニュー

右クリックのコンテキストメニューは、マークアップではなくフックである
`useContextMenu` で宣言し、Rust 側に投げられて macOS / Windows では本物の
`NSMenu` / `HMENU` がポップアップします。詳しくは専用の
[コンテキストメニュー](/docs/guides/context-menu)ガイドを参照してください。

## ダイアログ、クリップボード、通知、shell、ウィンドウ操作

レンダラーから安全に使えるネイティブ機能は `murasaki/native` から import します。
すべて Promise ベースで、リクエストID付きIPCをRustホストが直接処理します。

```tsx
'use client'

import { app, appWindow, clipboard, dialog, globalShortcut, notification, secureStorage, shell, systemPermission, tray, windows } from 'murasaki/native'

const files = await dialog.openFile({
  multiple: true,
  filters: [{ name: 'Images', extensions: ['png', 'jpg'] }],
})
await clipboard.writeText(files.join('\n'))
await notification.show({ title: '選択完了', body: `${files.length} files` })
await appWindow.setTitle('Import complete')
console.log(await appWindow.getLabel())
await windows.open('preview')
await shell.showItemInFolder(files[0])
```

| API | 操作 |
| --- | --- |
| `app` | `quit`（gracefulなapplication shutdown） |
| `dialog` | `openFile`, `openDirectory`, `saveFile`, `showMessage`(ネイティブOSメッセージボックス) |
| `clipboard` | `readText`, `writeText`, `readImage`, `writeImage`, `writeHtml` |
| `notification` | `show`(ローカル生成idを返す) |
| `shell` | `openExternal`（安全なURLスキームのみ）、`showItemInFolder`, `trashItem`, `openPath` |
| `secureStorage` | string値向けのOS-backed `get`, `set`, `delete` |
| `systemPermission` | macOSのcamera / microphone / screen recording / accessibility / input monitoring / location / full disk access向け`status`, `request` |
| `appWindow` | `getLabel`, `setTitle`, `setSize`, `minimize`, `toggleMaximize`, `show`, `hide`, `focus`, `close`, `setAlwaysOnTop`、状態取得 |
| `windows` | 宣言label向け`open`, `list`, `show`, `hide`, `focus`, `close` |
| `globalShortcut` | process-wideな`register`, `unregister`, `unregisterAll`, `onTriggered` |
| `tray` | `create`, `remove`, `setTooltip`, `setIcon`, `setMenu`, `onClick`, `onMenuItem` |

`app.quit()` とrootの `quit()` helperはいずれも `app:quit` が必要です。権限のない
secondary rendererからapplication全体を終了することはできません。

`dialog.showMessage({ title?, message, level?, buttons? })` はネイティブな
main-thread message boxを表示します(`level`は既定`'info'`、`buttons`は既定`'ok'`)。
押されたbuttonに解決されます(`'ok' | 'cancel' | 'yes' | 'no'`)。`title`は256
UTF-8 byte、`message`は4096 UTF-8 byteまでで、どちらも制御文字は拒否されます
(改行は`message`のみ許可)。`dialog:message`が必要です。

`clipboard.readImage()` は `{ width, height, pngBase64 }` または、clipboardに
imageがない場合は`null`を返します。`clipboard.writeImage({ pngBase64 })`
はデコードしてclipboard imageを置き換えます(デコード後のpixelは64 MiB、各辺は
16,384pxまで)。`clipboard.writeHtml({ html, altText? })` はHTMLと任意の
plain-text fallbackを書き込みます(`html`は1 MiB、`altText`は64 KiBまで)。
それぞれ `clipboard:readImage`, `clipboard:writeImage`, `clipboard:writeHtml`
が必要です。

`shell.trashItem(path)` は既存のfile / directoryをOSのtrash・recycle binへ
移動します。`shell.openPath(path)` は既存のlocal file / directoryをOSの既定
handlerで開きます(ダブルクリックと同様)。どちらもabsoluteでtraversalしない、
実在するpathが必要です。`shell.showItemInFolder`と同様、`shell:trashItem` /
`shell:openPath` capabilityは許可するpath subtreeへscopeできます。
`shell.openPath` はURLとしてparseできるものやUNCのnetwork / device pathも
拒否します。URLを開く場合は`shell.openExternal`を使ってください。

<Callout type="warning">
  **0.50 migration:** 以前の`quit()`はpermissionなしのraw IPCを送っていました。
  既存のnon-updater appで使用しているwindowには`app:quit`を追加してください。
  built-in updaterを有効にした場合だけ、検証済みinstall / restart handshakeの後方互換性を
  保つためprimary windowへ自動付与されます。
</Callout>

<Callout type="info">
  これらは `src/main.ts` から直接呼ぶAPIではなく、信頼済みレンダラー向けです。
  ブリッジはアプリと完全一致するoriginだけを受け付け、固定allowlistのコマンドだけを
  公開します。各rendererが使うcommandだけを `window.capabilities` /
  `windows[label].capabilities` で許可してください。structured grantではshell URL/path、
  target window label、OS permission名をallow/denyでscopeできます。他のargumentは
  command単位なので、権限を持つwindowに信頼できないremote contentを読み込まないでください。
</Callout>

## セキュアストレージ

信頼済みrendererがrefresh token、license値などの短いstringを永続化する必要があり、plain
fileへ保存したくない場合は`secureStorage`を使います。macOSではKeychain、Windowsでは
Credential Manager、Linuxではfreedesktop.orgのSecret Service D-Bus API
(gnome-keyring、KWallet、KeePassXCなど)を使用します。Linuxでは稼働中のSecret Service
providerが必要で、到達できない場合はすべての呼び出しがstructured errorで失敗します。その他の
未対応platformは明示的な`unsupported` errorを返します。どのplatformでもMurasakiが
plaintext fileへfallbackすることはありません。

```ts
import { secureStorage } from 'murasaki/native'

await secureStorage.set('refresh-token', token)
const saved = await secureStorage.get('refresh-token') // string | null
await secureStorage.delete('refresh-token')            // 未登録でも成功
```

必要なwindowだけへ操作ごとに独立してgrantします。

```ts title="murasaki.config.ts"
export default defineConfig({
  appId: 'com.example.notes',
  productName: 'Notes',
  window: {
    capabilities: [
      'secureStorage:get',
      'secureStorage:set',
      'secureStorage:delete',
    ],
  },
})
```

entryは`appId`とkeyからSHA-256で導出したidentifierでnamespace分離されるため、release間で
`appId`を維持してください。keyは空でない256 UTF-8 byte以下、valueは空でない2,048
UTF-8 byte以下です。NULは拒否され、native IPC bodyにも256 KiB上限があります。保存済み
dataが破損、非UTF-8、上限超過なら暗黙変換せずerrorを返します。

capabilityはkey別ではなく操作単位です。`secureStorage:get`を持つrendererは、そのapp
namespace内で既知または推測可能なすべてのkeyを読めます。Keychain / Credential Managerは
at-restのplaintext fileを避ける仕組みで、認可済みrenderer内のXSSからsecretを守るものでは
ありません。rendererが必要としないsecretはNode / server-only codeに置いてください。

## トレイアイコン

client componentから1つのsystem tray iconを作成できます。既定では
`config.icon` を使い、明示指定する場合は8-bit RGB/RGBA PNGを渡します。
操作ごとに独立したpermissionが必要です。

```ts
import { tray } from 'murasaki/native'

await tray.create({
  tooltip: '同期中',
  template: true,
  menu: [
    { id: 'open', label: 'Murasakiを開く' },
    { separator: true },
    { id: 'quit', label: '終了' },
  ],
  menuOnLeftClick: navigator.userAgent.includes('Mac OS X'),
  menuOnRightClick: true,
})
const unsubscribe = tray.onClick(({ button, double }) => {
  console.log({ button, double })
})
const unsubscribeMenu = tray.onMenuItem(async (id) => {
  if (id === 'open') await appWindow.show()
  if (id === 'quit') await app.quit()
})

await tray.setTooltip('同期完了')
await tray.setIcon('/absolute/path/to/synced.png')
await tray.setMenu([{ id: 'open', label: 'Murasakiを開く' }])
// 後で: unsubscribe(); unsubscribeMenu(); await tray.remove()
```

```ts title="murasaki.config.ts"
export default defineConfig({
  // ...
  capabilities: [
    'tray:create',
    'tray:setTooltip',
    'tray:setIcon',
    'tray:setMenu',
    'tray:remove',
    'window:show',
    'app:quit',
  ],
})
```

`template` はmacOS専用です。もう一度 `create` すると既存アイコンを置き換えます。
tray menuはevent駆動で、click可能な項目には一意な`id`が必要です。quitなどのprivileged
actionは、それぞれ本来のnative capabilityを通過します。process-wide iconを作成した
rendererを閉じるとiconも削除されます。

<Callout type="warn">
  Linuxのtrayはlibappindicatorを使うため、AppIndicatorをホストする環境が必要です
  (GNOMEではAppIndicator/KStatusNotifierItem Shell拡張機能が必要)。tray menuのclickと
  動的なicon/menu差し替えはmacOS/Windowsと同様に動作しますが、tray icon自体の
  click/double-click eventはLinuxでは発火しません — AppIndicatorには「attach済みmenuを
  表示する」以外のsignalがないためです。
</Callout>

## グローバルショートカット

信頼済みclient componentから、macOS / Windows / Linux(X11/XWayland)の
process-wide shortcutを登録できます。登録と解除は別々のdeny-by-default capabilityです。

```ts title="murasaki.config.ts"
export default defineConfig({
  appId: 'com.example.notes',
  productName: 'Notes',
  window: {
    capabilities: [
      'globalShortcut:register',
      'globalShortcut:unregister',
    ],
  },
})
```

```tsx
'use client'

import { useEffect } from 'react'
import { globalShortcut } from 'murasaki/native'

export function CaptureShortcut() {
  useEffect(() => {
    let active = true
    const unsubscribe = globalShortcut.onTriggered(({ id }) => {
      if (id === 'capture-region') startCapture()
    })

    void globalShortcut.register('CmdOrCtrl+Shift+K', 'capture-region')
      .catch((error) => {
        if (active) console.error('shortcutを利用できません', error)
      })

    return () => {
      active = false
      unsubscribe()
      void globalShortcut.unregister('capture-region')
    }
  }, [])

  return null
}
```

`register(accelerator, id?)`は`{ id, accelerator }`を返します。返されるacceleratorは
platform解決済みのcanonical値で、`CmdOrCtrl`はmacOSでCommand、Windows/LinuxでControlに
なります。`id`省略時はcanonical acceleratorがidです。`unregisterAll()`が解除するのは
呼び出したrendererの登録だけで、他windowの登録には触れません。

acceleratorは上限付きASCII stringで、1〜4個のmodifierの後に既知のkeyを1個置きます。
modifier重複、keyだけのshortcut、不正・未知のkey、lifecycle / OS予約chord（Command+Q、
Alt+F4など。LinuxにはOS-levelの予約listがありません — desktop環境ごとに異なるためです）、
重複id、重複accelerator、他appが取得済みのchordは拒否されます。同時登録は
processあたり64件までです。idは1〜128文字で、英数字と`.`、`_`、`:`、`-`、`+`を使えます。

所有権はrenderer windowに紐づき、close / disposeでその登録を自動解除し、app shutdownで
全登録を解除します。trigger eventはlive-onlyかつownerだけに届き、reload後のreplayは
ありません。

<Callout type="warn">
  LinuxのグローバルショートカットはX11またはXWayland必須です(内部で使用するcrateに
  ネイティブなWayland backendがないため)。純粋なWaylandセッション(`WAYLAND_DISPLAY`が
  設定され`DISPLAY`が未設定)では、`register`は何も登録せず失敗するのではなく、
  structuredな`unsupported` errorを返します。
</Callout>

<Callout type="info">
  parser、所有権、capability、macOS build、Windows x64/arm64 buildは自動検証します。
  OS-levelの利用可否は他のinstalled app、keyboard layout、remote desktop software、OS予約
  bindingにも依存するため、release前に各対応OSのpackaged appで実際のchordをsmoke test
  してください。
</Callout>

## システム権限

OSの同意とMurasaki renderer capabilityは別物です。packaged macOS appでは、用途説明と
任意の起動時requestをconfigに宣言できます。用途説明は`Info.plist`へ書き込まれ、camera /
microphoneの説明が欠けた状態でpromptしてappがcrashすることを防ぎます。

```ts title="murasaki.config.ts"
export default defineConfig({
  // ...
  systemPermissions: {
    macOS: {
      camera: {
        usageDescription: 'ビデオ通話でカメラを使用します。',
        requestOnLaunch: true,
      },
      microphone: {
        usageDescription: '音声通話でマイクを使用します。',
      },
      screenRecording: { requestOnLaunch: false },
      accessibility: { requestOnLaunch: false },
      inputMonitoring: { requestOnLaunch: false },
      location: {
        usageDescription: '近くのスポットを表示します。',
        mode: 'whenInUse',
      },
      fullDiskAccess: { requestOnLaunch: false },
    },
  },
  capabilities: [
    'systemPermission:status',
    'systemPermission:request',
  ],
})
```

client componentから文脈に合わせて要求する場合:

```ts
const status = await systemPermission.status('microphone')
if (status === 'notDetermined') {
  await systemPermission.request('microphone')
}
```

camera / microphone / locationのOS promptは非同期で完了するため、`request()`が最初は
`notDetermined`を返す場合があります。protected featureを有効にする前に、appが再び
focusされた時点で`status()`を再確認してください。

`requestOnLaunch`はpackaged macOS appに適用されます。developmentはterminal / Node hostの
identityで動くため、TCCの実動作はpackage buildから確認してください。Windowsのunpackaged
desktop appではcamera / microphoneを利用するdevice API側が同意を要求し、汎用的な起動時
promptはありません。そのためMurasakiは権限取得を装わず`unsupported`を返します。macOSの
screen recording / accessibility / input monitoringは初回とdenyを区別できない場合
`notGranted`です。7種類すべてmacOS専用です — WindowsとLinuxにはこれらTCC管理下の
promptに相当するOSレベルの機能がないため、権限取得を装わず全呼び出しで`unsupported`を
返します。

`location.usageDescription`はcamera / microphoneと同様必須で、
`NSLocationWhenInUseUsageDescription`へ書き込まれます。`mode: 'always'`を指定すると
`NSLocationAlwaysAndWhenInUseUsageDescription`も追加で書き込み(Appleはalways requestでも
when-in-useキーの存在を要求します)、when-in-useではなくalways-authorizationを要求します。

<Callout type="warn">
  `fullDiskAccess`はguidance-onlyです。macOSにはFull Disk AccessのTCC request APIが
  存在しないため、`request()`はSystem SettingsのFull Disk Accessペインを開いて
  userに自分で許可してもらうことしかできません — 権限取得を装うことは決してありません。
  `status()`はbest-effortのheuristicです(Full Disk Access自体で保護されている
  `~/Library/Application Support/com.apple.TCC/TCC.db`が読めるかを確認します)。
  通常の`granted` / `notGranted`に加え、heuristicで確信を持てない場合は
  `unknown`を返すことがあります。
</Callout>

## 組み込みのメニューアクション

項目の `action` は、関数の代わりに組み込みの `<Action.*/>` 要素の1つにできます —
これらは(OS 自身が処理する)ネイティブロール、または小さなクライアントサイドの挙動を
実行します:

| Action | 挙動 |
| --- | --- |
| `<Action.Copy />`, `<Action.Paste />`, `<Action.Cut />`, `<Action.SelectAll />`, `<Action.Undo />`, `<Action.Redo />` | ネイティブ OS の編集ロール |
| `<Action.Quit />` | ネイティブの終了ロール |
| `<Action.Reload />` | ウィンドウをリロードします(`location.reload()`） |
| `<Action.Navigate to="/path" />` | ルーター経由のクライアントサイドナビゲーション |
| `<Action.Run action={fn} />` | 通常の関数を実行します(関数を直接渡すのと同じです） |

## 自動更新

`useUpdate()` は、更新の確認・ダウンロード・インストールを行います — その確認/ダウン
ロードのロジックは Node 上で動作し、コンテキストメニューやアプリメニューが使う IPC
ブリッジではなく、アプリの他の部分を配信しているのと同じローカル HTTP サーバー(Server
Actions や API Routes と同じ仕組み)経由でアクセスされます。`<UpdateButton />`
(こちらも `murasaki` から、`@murasakijs/ui` でスタイリング)は、それをラップした
すぐに使えるボタンです:

```tsx
import { useUpdate } from 'murasaki'

const { status, latest, check, download, install } = useUpdate()
```

`status` は `idle → checking → available → downloading → ready`(または
`not-available` / `error`)と遷移します。セットアップはコマンド2つだけです — マニフェ
ストの形式、セキュリティモデル、GitHub Actions でのリリースワークフローについては、専
用の[自動更新](/docs/guides/auto-update)ガイドを参照してください。

<Callout type="warn">
  structured capability scopeはshell URL/path、target window label、OS permission名だけで、
  global shortcut accelerator、dialog defaultなど他のargumentはcommand単位です。
  設計前に
  [プラットフォーム機能状況](/docs/core-concepts/platform-feature-status)を確認してください。
</Callout>
