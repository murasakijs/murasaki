# Murasaki リファレンスアプリ

[English](./README.md)

ここに置くアプリは、Murasaki を実際の製品開発へ使えるか検証するためのリファレンス実装です。
静的な UI ギャラリーや、固定データをライブ情報のように見せるデモにはしません。サンプルデータを
無効にしても利用でき、ストレージ、プロセス、ネットワーク、配布の経路が実際に動作することを
完成条件とします。

## アプリ一覧

| アプリ | 対象 | 製品 | 主に検証するMurasakiの機能 |
| --- | --- | --- | --- |
| [Papelle](./papelle) | 個人 | ローカルファーストのブロック型ナレッジワークスペース | ファイル、SQLite、Node Main、オフライン状態、添付、入出力、任意のセルフホスト共同編集 |
| [Oscilla](./oscilla) | 開発者 | APIテスト・自動化・ログ監視ワークベンチ | 実際のHTTP／GraphQL／WebSocket通信、セキュアストレージ、常駐処理、ファイル／Dockerストリーム、ローカルモックサーバー |
| [Orglia](./orglia) | 組織 | セルフホスト型の統合業務スイート | 複数ページ、関連業務フロー、RBAC、監査記録、PostgreSQL同期、帳票とエクスポート |

3つの製品は、それぞれ独立した名前、アイコン、配色、情報設計、データモデルを持ちます。
共通して見えるブランドではなく、共通して利用するフレームワークがMurasakiです。

## 実装時に参照する正規情報

フレームワーク連携を実装・変更する前に、次のリポジトリ内情報を確認します。

1. Docsの `/llms.txt`、`/llms-api.txt`、ページ単位のMarkdown。
2. 読み取り専用の `@murasakijs/mcp`。`list_capabilities` で機能IDを取得し、
   `check_compatibility` で対象OSごとの対応状況を確認します。
3. `packages/murasaki/capabilities.json`。ガイドと機能ラベルが食い違う場合の正規情報です。
4. `get_config_schema` が返す公開設定スキーマ。

`doctor` が確認するのはプロジェクト構造です。`pass` になっても、アプリが実行できることの
証明にはなりません。

## 共通要件

- 日本語・英語に対応する。
- 主要操作をキーボードだけで完了でき、WCAG 2.2 AA相当の意味構造とコントラストを備える。
- 製品ごとに独自のアイコンとデザインシステムを用意する。
- macOS、Windows、Linuxでの動作を目標とし、未対応機能を擬似実装で隠さない。
- ローカルデータにはSQLiteを使用する。複数人で共有する機能は、Docker Composeで起動する
  任意のPostgreSQLサービスを利用する。
- 通常の初回起動では、明示的に「サンプルデータ」と表示した現実的なワークスペースを用意する。
- 設定画面からサンプルデータを初期状態へ戻せるようにする。
- `--no-sample-data` を付けると空のワークスペースで起動する。
- リファレンス機能の利用に外部SaaSアカウントを要求しない。
- 読み込み中、空、権限不足、オフライン、部分的な失敗、復旧状態も製品UIとして実装する。
- 破壊的な操作は確認を求め、可能な範囲で復元できる結果を残す。

サンプルレコードを業務フローの説明に使うことはできます。ただし、ライブ状態、リクエストログ、
同期状態、テスト結果、性能値は、説明している処理から実際に取得しなければなりません。

## 製品要件

### Papelle

Papelle は、生成りの紙とインクの温かさに、現代的な文具UIを組み合わせます。中心となるのは、
オフラインでも利用できる個人用ワークスペースです。

- キーボード操作と並べ替えに対応した、Notionに近いブロックエディタ。
- ページ階層、ページ間リンク、バックリンク、タグ、全文検索。
- 標準Markdownのインポート／エクスポート。ユーザーデータを独自形式へ閉じ込めない。
- 画像、PDF、音声の添付、整理、プレビュー。
- 同じレコードをテーブル、カンバン、カレンダーで切り替えるデータベース。
- ローカル永続化と、競合を壊さないオフライン編集。
- Docker Composeで起動する任意の共同編集サービス。独立した2クライアント間で収束を確認する。

### Oscilla

Oscilla は暗い計測画面と高コントラストの信号色を使います。固定されたリクエスト行ではなく、
実際の通信とプロセスを観測します。

- REST、GraphQL、WebSocketのリクエストワークスペース。
- OpenAPIとPostman Collectionの取込、検証、修正可能なエラー表示。
- 開発・ステージング・本番環境の切替。秘密情報をエクスポート対象から除外し、利用可能なOSでは
  認証情報ストアで保護する。
- 連続シナリオ、値の受け渡し、アサーション、再実行可能な結果。
- OpenAPIから起動するローカルモックサーバー。成功、遅延、エラー応答を切り替えられる。
- Oscillaの通信、ローカルログファイル、Dockerログを統合したタイムライン。レベル、サービス、
  リクエストIDで絞り込める。
- 常駐ストリームの切断、再試行、打ち切り、バックプレッシャーを明示的に扱う。

### Orglia

Orglia は明るく、役割に応じて表示が変わる業務ワークスペースです。モジュールごとに識別色を
持たせながら、ナビゲーションと関連データモデルは統一します。

- プロジェクト、CRM、申請、在庫・受発注、シフト、分析、インシデント、管理を切り替える
  サイドバーナビゲーション。
- 顧客 → 商談／案件 → 受注 → 在庫引当 → 売上分析が連動する業務フロー。
- 申請フォーム、多段階承認、却下、差し戻し、変更できない監査記録。
- シフト希望、必要人数、勤務制約、自動案、管理者による調整、確定・公開。
- 重要度、担当者、期限、タイムライン、エスカレーション、解決、事後レビューを含む
  インシデント管理。
- 管理者、マネージャー、一般メンバーのRBAC。ナビゲーションを隠すだけでなく、データ操作側で
  権限を強制する。
- セルフホストサービス内でのテナント分離。
- 自由に配置できるダッシュボード、期間・部署・担当者フィルター、CSV／PDF出力。

## 検証レベル

後段の検証が通っても、前段の失敗は解消されたことになりません。

| レベル | 証拠 | 証明できること |
| --- | --- | --- |
| L0 | MCP互換性レポートと制約確認 | 計画中の機能を実装済みとして設計していない |
| L1 | 型検査、単体テスト、本番クライアントビルド | ソースと分離されたロジックがコンパイルできる |
| L2 | `murasaki dev` 上の操作テスト | レンダラー、Node.js、ルーティング、実データ経路が連携する |
| L3 | 再起動、空起動、リセット、オフライン、復旧テスト | 状態とライフサイクルが実装されている |
| L4 | 2クライアント／外部プロセスとの統合テスト | 共同編集、通信、ログ、認可が実際に動く |
| L5 | 対象OS上でバンドルを起動 | 配布アプリと同梱Node.jsが起動する |
| L6 | インストール、初回起動、更新／削除テスト | ソースツリー外で配布手順が動く |
| L7 | 起動時間、アイドルメモリ、成果物サイズの再現可能な計測 | 日付と測定方法を含む性能根拠がある |

L1だけではリファレンスアプリの完成としません。到達できないOSやレベルがある場合は、正確な
阻害要因を各READMEと公開機能ステータスへ記載します。

## フレームワークへのフィードバック

リファレンスアプリから不足APIが見つかることは問題ではありません。アプリ固有のポーリング、
固定ステータス、ブラウザだけのモック、非公開のネイティブ呼び出しで隠さず、次を記録します。

1. ユーザーから見た要件。
2. 最小再現。
3. OSごとの現在の機能判定。
4. 必要な公開APIと権限境界。
5. 解決と判断するために必要なランタイム／配布テスト。
